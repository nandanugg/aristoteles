# Roles and staffing

A role describes a broad kind of work and the output it owns. Give it a stable ID, summary, introduction and concrete duties. A task pins the accepted role responsibility and direction. Stages tell the role what to do. Standards and rules tell it how the result will be checked.

The host coordinates the work. The pipeline interprets guidance, reviews larger work and assesses raised problems. Work roles deliver concrete outputs. The host and pipeline are two roles even when one staff serves both.

Staffing covers every role with an assigned staff. Use one list of subscriptions and reference it from the staff assignments. Keep the host’s estimate when it has an evidence basis, otherwise use NoEstimate. Record the model, account, launch command, subagent count and reason for each staff. The owner adjusts staffing on the review path.

Match the model to the judgment:

- Use the strongest model for host and pipeline work, including meaningful splits and guidance revisions.
- Use a strong model for parent reviews and work dominated by prompt rules.
- Use a capable model for a design or document section that needs judgment.
- Use a light model for mechanical work such as formatting or applying established tests.

The host and pipeline each need access to a subagent. A reviewer with a positive allowance waits for its own staff slot when busy. A reviewer with zero allowance uses the host’s queue.

A validator or test is a command on a rule, scoped to the result it checks. A judgment check asks a prompt and records quoted material. The task names the reviewing role. Individual rules describe conditions and evidence.

The owner changes responsibility through a reviewed proposal. When the pipeline finds a problem in guidance, it reports the available evidence so the owner can review the proposed changes.
