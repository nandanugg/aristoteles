# Reviewing a draft of a direction

Read the draft (`work direction show <draft>`) and what it answers: the suggestion, or the
Reject. Ask each question below of each entry. Accept with evidence only when each answer is
good. Else reject with one reason in this form:
`<entry id>[#<header>]: <the problem>; <what would fix it>`.

## The questions

1. **Correct.** The suggestion or the Reject gives the aim and the concerns. Example: "a
   direction for a code factory, with the aim X and the concerns Y". Does this text lead a model
   to the correct work for that aim, and does it hold each concern?
2. **Vague.** Is a word or a sentence vague (handle, properly, good, clean, as needed)?
3. **More than one reading.** Can a sentence mean two things to two models?
4. **Twice.** Does an entry say one thing twice, or do two entries say one thing?
5. **Context density.** Does the first paragraph of each entry say the whole entry? Does the
   text under each header stand alone? Is there filler that a model reads and does not use?
6. **Negative parallelism.** Does a sentence say "not X but Y", where "Y" alone is enough?
7. **Concise.** Can a sentence go, with nothing lost?
8. **Checkable.** Can a reviewer check each rule on one result, and give evidence for it?
9. **Fit.** Does each standard follow from the words of its direction? Does each rule check its
   standard?

## The evidence of an accept

Name where you read and what you saw, one line for each entry that you checked:
`--evidence="<draft>, <entry id> | <what you saw>"`.
